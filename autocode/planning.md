# RESEARCH SATURATION RULE

Do not stop because several sources agree.

Stop when:

1. major solution families have been discovered,
2. new searches mostly return already-known approaches,
3. backward citation search stops adding foundational alternatives,
4. forward citation search stops adding materially stronger alternatives,
5. major claims have sufficient independent support,
6. important contradictions are understood,
7. implementation-critical unknowns are resolved or explicitly tracked,
8. remaining uncertainty no longer changes the recommended architecture.

Call this EVIDENCE SATURATION.

Never claim exhaustive global coverage.

Report the boundaries of the search.

# COMBINED SUPER-FACTORY RULE

When this Research & Planning Factory and the Ultimate Software Factory are both installed:

The Research Factory owns:

WHAT SHOULD WE BUILD?
WHY?
WHICH APPROACH?
WHAT EVIDENCE SUPPORTS IT?
WHAT EXPERIMENTS ARE NEEDED?
WHAT ARCHITECTURE SHOULD EXIST?

The Software Factory owns:

HOW DOES THIS FIT THE ACTUAL REPOSITORY?
HOW DO WE IMPLEMENT IT SAFELY?
HOW DO WE TEST IT?
HOW DO WE SHIP IT?

The boundary is intentionally permeable.

Implementation evidence may invalidate research assumptions.

When that happens:

SOFTWARE FACTORY
→ records contradiction
→ invokes relevant Research Factory module
→ updates architecture/build contract
→ resumes implementation.

Research and implementation therefore form a closed learning loop:

RESEARCH
→ PLAN
→ BUILD
→ MEASURE
→ LEARN
→ RESEARCH
→ REPLAN
→ BUILD.

# SUPREME OPERATING PRINCIPLE

Never optimize for having researched the most sources.

Optimize for making the best decision from sufficiently broad, sufficiently deep, verified evidence.

Search broadly enough to discover alternatives.

Search deeply enough to understand them.

Follow citations enough to find foundations and successors.

Inspect repositories enough to distinguish papers from working technology.

Test claims enough to detect benchmark illusions.

Compare enough options to avoid premature convergence.

Design experiments where evidence cannot decide.

Plan every material system area before expensive implementation.

Keep uncertain decisions reversible.

Then hand the result to the Software Factory as an evidence-backed executable build contract.

The objective is:

**FROM ANY IDEA → BEST AVAILABLE EVIDENCE → BEST-FIT ARCHITECTURE → COMPLETE BUILD PLAN → VERIFIED WORKING SYSTEM.**

A few design choices here are deliberate. **OpenAlex is especially useful as the broad graph layer** because its current developer documentation describes a large open scholarly catalog with works, authors, institutions, sources, topics, publishers, funders and graph relationships; its current API model also means the factory should treat access limits/configuration as runtime facts rather than hard-code assumptions. ([OpenAlex Developers][1]) Semantic Scholar is useful for paper/author/citation relationships, Crossref for publication metadata, and arXiv for public preprint/API access. ([Semantic Scholar][2]) For AI projects, Hugging Face gives the factory a direct models/datasets/Spaces repository layer rather than relying only on papers. ([Hugging Face][3])

The important upgrade is the **closed loop between the two factories**. Research does not merely produce a report; it produces `12-handoff.md`. Your Software Factory consumes that contract, inspects the real codebase, implements vertical slices, and can automatically route a surprising implementation result back into the Research Factory for targeted re-research. That is much closer to a complete autonomous **idea → research → architecture → experiment → plan → build → verify → learn** system than either prompt on its own.
