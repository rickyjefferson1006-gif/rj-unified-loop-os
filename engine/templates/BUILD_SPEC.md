# Build Specification

## Outcome

State the exact business and user outcome.

## Users and roles

Identify users, administrators, service accounts, external systems, and prohibited actors.

## Required capabilities

List measurable capabilities. Each will receive a requirement ID and acceptance criteria.

## Data

Identify data types, sensitivity, source, ownership, retention, deletion, residency, and audit requirements.

## Integrations

List APIs, models, databases, identity providers, payment systems, messaging systems, and deployment platforms.

## Constraints

Record budget, schedule, stack, licensing, compliance, accessibility, performance, availability, and operational constraints.

## Non-goals

State what the build must not do.

## Deployment environments

Define local, development, staging, production, and disaster-recovery environments.

## Approval boundaries

Identify actions requiring human approval, including production deployment, data deletion, billing changes, external communications, and credential changes.
